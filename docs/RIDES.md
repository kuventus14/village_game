# 놀이기구 틀 — 새 기구를 레지스트리에 붙이는 법 (2단계용)

1단계(2026-11-04)에 만든 것: **대관람차(ferris)·회전목마(carousel)·꼬마기차(train)**. 2단계 A(같은 날): **드롭타워(drop)·바이킹(viking)·회전그네(swing)·롤러코스터(coaster)·후룸라이드(flume)**. 2단계 B(같은 날): **범퍼카(bumper)·회전 찻잔(teacups)** — 탄 사람이 직접 조작하는 기구, 아래 4·7. 이제 10종 모두.
부지·자리(`RIDE_SLOTS`)·길은 `docs/PARK.md`, 이 문서는 **기구 하나를 더하는 방법**만.

## 1. 기본 생각
- 좌석 위치는 **서버 시각만으로 정해지는 순수 함수** `pose(seat, t)` → 서버·모든 화면이 같은 값을 계산. 위치를 네트워크로 보내지 않는다.
- 화면은 서버 시각을 `welcome.rides.now`·`ride` 메시지의 `now` 로 맞춘다(`rides.js` 의 `off`). 오차 수십 ms.
- 서버(`rides.js`)가 심판: 탑승 창·거리·자리 배정·하차. 탄 사람은 `p.ride = { id, seat }`, 이동('m')은 무시(`frozen`), 서버는 tick 마다 `p.x/p.z` 를 자리로 맞춤(장소·말풍선·봇용, 방송 안 함).
- 회차(round): 승차 창 → 운행 → 하차. 끝없이 도는 기구(기차)는 "역에 설 때만 타고 내림".

## 2. `public/ridesdata.js` 에 기구 하나 = `RIDES[id] = { … }`
`id` 는 `RIDE_SLOTS` 의 id 그대로. **넣는 순간 park-site.js 의 '준비 중' 표지가 사라짐.** world.js 를 import 하지 말 것(`./parkdata.js` 는 됨).

| 이름 | 뜻 |
|---|---|
| `id, name, icon` | 'viking', '바이킹', '🏴‍☠️' |
| `status` | 이름표 상태 키 (예 `'rideViking'`, 다른 STATUS 와 겹치지 않게). 파일 끝 반복문이 `RIDE_STATUS` 에 `[icon, '○○ 타는 중']` 을 넣음 |
| `seats` | 자리 수 (0 ~ seats-1) |
| `reach` | 탈 수 있는 거리(m): 내 위치 ↔ 가장 가까운 빈자리의 `pose` |
| `sit` | 앉는 자세 = `avatar.animate` 의 `seat.kind` (`'park'` 기대어 앉기, `'hold'` 걸터앉아 기둥 잡기, 그 밖은 기본 앉기) |
| `cam` | `{ pitch, dist }` 타는 동안 시점 (`rides.js` 가 `aim` 으로 바꿈, 내리면 원래대로) |
| `pose(seat, t)` | → `{ x, y(앉는 면 높이), z, ry }`. **순수 함수, t = 서버 ms**. 회차 경계에서도 이어져야 함(점프 금지) |
| `open(t)` | 지금 탈 수 있으면 `{ seats: [자리…], left }`, 아니면 `{ wait(ms), msg }` (안내 패널·거절 문구에 그대로 씀) |
| `board(t)` | 탄 사람 기록에 붙일 값 (예 `{ round: n }`) |
| `exitOk(rider, t)` | 스스로 내릴 수 있나 (멈춰 있을 때만 등) |
| `due(rider, t)` | 서버가 지금 내려 줘야 하나 (회차 끝) |
| `exit(seat, t)` | → `[x, z, ry]` 안전한 내릴 자리 (서버가 `resolve` 로 한 번 더 밀어냄). **걸을 수 있는 빈 땅**이어야 함 |
| `input?(rider, m, t)` | (조작 기구만) 아래 4 참고 |

- 충돌은 `RIDE_RECTS.push([x0,z0,x1,z1])` · `RIDE_CIRCLES.push({x,z,r})` — **다시 대입 금지**(world.js 가 배열을 가리킴). 대로 끝·`entry` 점은 걸어서 닿아야 함(`test-park.mjs` 가 확인).
- export 이름이 parkdata·zoodata 와 겹치면 `export *` 가 조용히 버림 → 새 이름은 `RIDE`/`ride`/기구 이름으로 시작.
- 시간 도우미: `trap(u, T, ta)` (사다리꼴 속도 0→1). 각도는 회차마다 정수 바퀴로 쌓아 회차 경계에서 이어지게(`ferrisAt`·`carouselAt` 참고).

## 3. `public/rides.js` 에 모양 하나
- `buildXxx(root, lite)` → `{ g, update(t) }` 를 만들고 `createRides` 안에서 부름(매 프레임 `update(now())`). 다른 사람·나는 `pose` 로 이미 자리에 앉혀지므로 **모양만** 맞추면 됨.
- 같은 재질끼리 합치기: `Kit` + `buildKit(kit, group, false)` (키 `plain`·`shine`·`glow`·`wood`·`stone`…). `glow` 키는 밤에 자동으로 밝아짐(`nightGlow`).
- 같은 모양 여럿(곤돌라·객차): `kit.geometry('a')` → `InstancedMesh` (몸통은 `setColorAt` 으로 색), 위치는 매 프레임 `setMatrixAt`.
- 모양 전체가 움직이면 그룹의 rotation 으로, 부분마다 조금씩(회전목마 동물 위아래)은 셰이더 `patch` 로(정점 속성 + uniform).
- 거리 숨김: `update` 끝의 `visible` 거리 검사에 한 줄. `Q.lite`/low 면 전구 수를 줄임.
- 안내 패널의 '가까운 탑승구'는 `nearRide(me)` 에 한 줄, 안내 문구는 `ui()` 의 `sub` 표에 한 줄.
- 소리는 `sfx.js` 의 `SND`(한 번)·`BEDS`(계속) 에 더하고 `sound()` 에서 거리로 크기를 정함(아주 작게).

## 4. 조작이 필요한 기구 (범퍼카 운전·찻잔 속도) — 2단계 B 에서 실제로 만든 틀
- 기구 전체 상태 `sim`: `init()` → sim (크기 고정: 차 10대·찻잔 8개 → 하루 종일 켜 둬도 안 늘어남). 서버 `rides.js` 가 기구마다 하나씩 들고, `pose(seat, t, sim)`·`input(rider, m, t, sim)` 에 넘김. 화면도 같은 모양의 sim 을 들고 `seat()` 에 넘김. **sim 이 없으면 제자리·속도 0** 이라 3절의 공용 시험(연속성·내릴 자리)이 그대로 돎.
- 화면 → 서버: `{ t: 'ride', op: 'in', …값 }` (탄 사람만, `input` 이 있을 때만). `input` 이 값을 검사(범위·연타)해 `rider.st` 나 sim 을 고치고, 모두에게 알릴 값을 돌려주면 `{ op: 'in', id, r, …값, now }` 방송 (null 이면 방송 안 함).
- 서버가 계산하는 기구는 `step(sim, t, 그 기구에 탄 사람들)` → 돌려준 값을 tick(20Hz)마다 **기구 둘레 `hear` m 안 사람에게만** `{ op: 'bc', r, …값, now }` 로 보냄. 늦게 온 사람: `snapshot().sim[id] = snap(sim)` → 화면 `load(sim, 값)`.
- 입력 받는 곳: game.js `control()` 이 `RIDE.busy()` 면 걷기 입력(키보드 WASD·방향키 + 폰 왼쪽 조이스틱, ix 오른쪽+ · iy 앞+)을 `RIDE.drive(ix, iy)` 로 넘기고 걷지 않음 → 새 버튼 없이 PC·폰이 같이 됨. 버튼이 더 필요하면 탄 동안 패널(`ui()`)에 `data-a` 버튼.

## 1단계 숫자 (ridesdata.js 상수)
- 대관람차: 반지름 28·축 31, 곤돌라 12 × 4자리. 한 회차 97초 = 곤돌라 0·1·2 를 차례로 아래에 7초씩 세움(그때만 탐) → 남은 300° 운행. 탄 사람은 딱 한 바퀴 돌고 처음 자리에서 내림.
- 회전목마: 24자리(바깥 12 · 안쪽 12, 말·토끼·곰), 승차 18초 → 60초 동안 3바퀴(7초 가감속), 위아래 ±0.32m. 다음 회차 시작에 모두 내림.
- 꼬마기차: 기관차 + 객차 4량(16자리), 최고 12m/s, 역 3곳에서 12초 정차, 한 바퀴 약 145초. 역에 설 때만 타고 내림, 안 내리면 한 바퀴 뒤 처음 역에서 내려 줌.

## 2단계 A 숫자 · 새로 배운 점 (2026-11-04)
- 한 회차(승차 창 포함): 드롭타워 39초(승차 16 · 12초 올라감 · 꼭대기 4초 · 0.75g 낙하 → 브레이크, 최고 17m/s) · 바이킹 50초(승차 14, 최대 54°, 최고 9m/s) · 회전그네 60초(승차 15, 5바퀴, 기울기 41°) · 롤러코스터 67초(승차 20, 꼭대기 17.5m, 최고 17m/s, 레일 336m) · 후룸라이드 85초(승차 13, 3척이 3.5초 간격, 낙하 8.2m, 최고 약 12m/s).
- 자리: 드롭타워 8 · 바이킹 16(양쪽 절반이 마주 봄) · 회전그네 24 · 롤러코스터 4량×4 · 후룸 3척×6. 다섯 다 `stdRide(K, {…})` 한 줄로 open·board·exitOk·due 를 얻음(승차 창 = 회차 시작 `K.load` ms, 다음 회차 시작에 내려 줌). 회차 끝엔 늘 처음 자리(정수 바퀴) → `exit(seat)` 는 시각과 상관없음.
- **길 따라 가는 기구**(롤러코스터·후룸): `loopPath(출발점, 조각[L/A], 높이 꺾은선, 고르게 폭)` → `at(s)` 3D 닫힌 길. 움직임은 `runTable(path, v(s,y), s0, 출발가속, 정지감속)` 이 시간표를 미리 만들어 `at(ms) → 간 거리` (빠르기 = 사슬 구간은 고정, 꼭대기부터 에너지 − 마찰). 배·차량이 여럿이면 출발점마다 시간표를 따로(후룸: 배 k 는 5.6k m 뒤에서 출발해 같은 물길 빠르기를 따름 → 서로 안 겹침, 시험).
- 화면: `sweep(path, s0, s1, step, 단면, 색)` 하나로 레일 관·등뼈·물길 U자·물 띠를 뽑음(양면 재질 키 `two`). 차량·배는 `pathM` (길 방향 3D 자세) 인스턴스. **물 띠는 MeshBasic 이라 양면으로** (한 면이면 위에서 안 보임 — 한 번 데임).
- 시점: `follow` 의 yaw 는 '카메라가 놓이는 쪽'(바라보는 쪽 + π). 롤러코스터·후룸은 내리막에서 뒤쪽 레일이 카메라보다 높아 레일 아래로 묻힘 → 내려가는 기울기만큼 pitch 를 올림(완만히 따라감, 1.4/s). 드롭타워는 뒤에서 보면 탑에 가려서 바깥 비스듬히 위(yaw = ry + 1.2, pitch 0.5). 바이킹은 북쪽 옆에서 고정(yaw π).
- 롤러코스터 레일은 슬롯 밖 북쪽 풀밭(매점·드롭타워 사이)으로 나갔다 옴: 가로 순환길 위 최저 5.7m(시험 4.5m↑). 기둥은 7m 마다, 길·가로등·매점·선로 옆은 건너뜀(30개, 충돌 원 r 0.35). 후룸 물길은 걸어서 건넘(충돌은 오르막 받침·동굴 양옆 바위만).
- 그리기 호출(1280×720 높음, 기구를 숨겼다 켜서 잰 차이): 드롭타워 +10 · 바이킹 +14 · 회전그네 +11 · 롤러코스터 +17 · 후룸 +17. 공원 전경 310콜·72만 삼각형.
- 봇: 'fun' 의 `at` 표에 다섯 줄(승강장·둘레). 20분 시뮬레이션(80봇)에서 새 기구 5회 탐(무작위라 기구마다 0~2).

## 7. 범퍼카·회전 찻잔 (2단계 B, 2026-11-04) 숫자 · 배운 점
- **범퍼카** (96초 = 승차 20 · 운행 70 · 제자리로 6, 차 10대 1인승): 서버가 `bumperStep(cars, dt)` (ridesdata.js, 시계·난수 안 씀, 25ms 쪼갬)로 앞뒤 가속 3.4·브레이크 7·끌림, 옆 미끄럼 grip, 최고 4.6m/s(부딪혀도), 핸들 2.1rad/s(후진은 반대), 벽 반사 0.7, 차끼리 원(r 1.0) 충돌 → 겹침 밀어내기 3번 + 빠르기 주고받기. 방송 = 차마다 [x,z,a,vx,vz]×100 정수(227바이트, 20Hz → 가까운 사람 1명당 약 4.6KB/초, 아무도 안 타고 다 멈추면 안 보냄). 입력 `{u, s}` 는 0.25 단위, 1.5초 새 입력이 없으면 손 뗀 것.
- 화면: **내 차만 같은 bumperStep 으로 예측**(다른 차는 복사본으로 넣어 바로 튕기는 느낌), 서버 값이 오면 0.06초 앞당겨 비교해 30%씩 당김(2.5m 넘게 어긋나면 순간이동, 나와 부딪힌 순간엔 빠르기를 서버 값으로). 다른 차는 받은 빠르기로 이어 가며 부드럽게 따라감. 부딪힘 목록 → 반짝 불꽃 + '통!'(sfx `bonk`).
- 경기장: 사람은 **로비(대기 줄)까지만** 걸어 들어오고 차 바닥은 늘 충돌 네모(문 닫힘 연출 대신 — resolve·test-park 의 '갇힌 땅' 검사가 시간과 상관없는 충돌만 다뤄서, 걷는 사람이 차에 치일 일도 없음). 차는 로비 앞에 한 줄로 서서 손만 뻗으면 탐(reach 5).
- 실내 시점: 벽·지붕 = 바깥 껍데기(outer) + 안쪽 면(한쪽만 그리는 Plane). **내가 건물 안이면 outer 를 숨김** → 카메라가 벽 밖에 있어도 안쪽 면은 뒷면이라 안 그려져 안이 보임(인형의 집 방식). 마을 건물의 camShrink 를 안 건드림.
- **회전 찻잔** (87초 = 승차 15 · 운행 72, 찻잔 8 × 4자리): 회전판은 시간만(3바퀴, 8초 가감속). 찻잔 c 의 자기 회전 ψ = a0 + w·(G(t) − G(t0)), G = 운행 시간을 같은 사다리꼴로 누적한 초 → 승차 중 0, 운행 끝에 살며시 멈춤, 회차가 바뀌면 그 회차 끝에 멈춰 있고 빠르기 0 부터(서버가 지울 일 없음). 빠르기 0~5칸 × 0.85rad/s, 0.35초에 한 칸, 운행 중만. 바뀔 때만 방송(작음, 모두에게). 시점은 찻잔이 아니라 회전판 각을 따라감(멀미 방지, 1.4/s).
- 그리기 호출(1280×720 높음, 숨겼다 켠 차이): 범퍼카 +18~20 · 회전 찻잔 +17 (목표 60 이하). 봇: 'fun' `at` 표에 두 줄 + 탄 봇이 범퍼카는 0.4~1.1초마다 대충 운전(벽이 가까우면 가운데로), 찻잔은 가끔 빠르게/느리게 — 손님과 같은 메시지.
